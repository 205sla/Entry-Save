## 빠른 진단 명령 (콘솔 복붙)

페이지 로드 후 게임 영역 클릭해 user gesture 발생시킨 뒤, DevTools 콘솔에서:

```js
// 1) inject.js가 두 frame 모두에서 로드됐는지
console.log('top __esmL:', window.__entrySaveManagerLoaded, '| ESM:', typeof ESM);
console.log('iframe __esmL:', window.frames[0]?.__entrySaveManagerLoaded, '| ESM:', typeof window.frames[0]?.ESM, '| Entry:', !!window.frames[0]?.Entry);
```

```js
// 2) @ 변수/리스트 현재 상태
const f = window.frames[0];
const vars = f?.Entry?.variableContainer?.variables_ || [];
console.log('@ 변수:', vars.filter(v => v.name_?.startsWith('@')).map(v => ({ name: v.name_, value: v.value_ })));
const lists = f?.Entry?.variableContainer?.lists_ || [];
console.log('@ 리스트:', lists.filter(l => l.name_?.startsWith('@')).map(l => ({ name: l.name_, len: l.array_?.length })));
```

```js
// 3) 후킹 상태
const f = window.frames[0];
const block = f?.Entry?.block;
const funcKeys = block ? Object.keys(block).filter(k => k.startsWith('func_')) : [];
funcKeys.forEach(k => console.log(`  ${k}._isSaveMgrHook:`, !!block[k]?.func?._isSaveMgrHook));
console.log('engine state:', f?.Entry?.engine?.state);
console.log('toggleRun has boundOriginal:', f?.Entry?.engine?.toggleRun?.toString?.().includes('boundOriginal'));
```

```js
// 4) 저장 데이터 현황
console.log('localStorage 키들:', Object.keys(localStorage).filter(k => k.startsWith('entry_save_')));
const id = location.pathname.split('/').pop().split('?')[0];
console.log('현재 ID 추정:', id);
console.log('entry_save_<id>:', JSON.parse(localStorage.getItem('entry_save_' + id) || 'null'));
console.log('entry_save_ws_<id>:', JSON.parse(localStorage.getItem('entry_save_ws_' + id) || 'null'));
console.log('entry_save_project_<id> (v1.3.0 잔재):', JSON.parse(localStorage.getItem('entry_save_project_' + id) || 'null'));
```

## 흔한 증상 → 원인 매핑

| 증상 | 의심 원인 | 확인 방법 | 해결 |
|---|---|---|---|
| `Uncaught ReferenceError: ESM is not defined` | MAIN world manifest 주입과 fallback 주입 순서·wrapper 격리 문제 | inject.js 초기 진입부, fallback shared.js 주입 로그 | 현재 공개 구현은 v1.3.6 롤백 이후 `var ESM` 유지. `window.ESM`/`globalThis.ESM` 변경은 테스트+실사이트 검증을 갖춘 별도 실험으로만 진행 |
| 변수가 1로 안 변함 / 자동 로드 안 됨 | engine.state가 'stop'에서 안 변함 (autoplay restriction) | 진단 #3에서 `engine state: stop` | 사용자에게 페이지 클릭 안내 ([01-문제-해결-기록.md](01-문제-해결-기록.md) "/project/ 자동 실행") |
| `func_xxx._isSaveMgrHook: false` | 후킹 미설치 | 진단 #3 | inject.js IIFE가 ESM 에러로 죽었거나 init() throw — 콘솔 빨간 에러 확인 |
| 같은 변수가 다른 값으로 나옴 (ws ↔ project 혼선) | namespace 분리 안 됨 | 진단 #4의 키들 확인 | pageType 핸드셰이크 동작 확인 ([Entry pageType 핸드셰이크 설계](공통/entry-page-type-handshake.md)) |
| @가져오기가 안 가져옴 | 소스 작품의 namespace 불일치 | 진단 #4에서 `entry_save_<sourceId>` 존재 여부 | 소스 작품에서 한 번 `@저장` 시켜 새 키 생성 |
| 후킹은 됐는데 `@저장` 호출이 wrapper로 안 옴 | Entry가 schema.func를 캐시했거나 재생성 | toggleRun 후킹은 됐는데 @저장만 안 되는지 비교 | hookFunctionCalls 폴링 재시도가 동작하는지 확인 |
| 콘솔에 inject.js 로그가 하나도 없음 | (a) 확장 미reload 또는 (b) 캐시된 옛 inject.js가 IIFE 플래그 점령 | 확장 reload 후 동일한지 | 아래 "확실한 재로딩 절차" 따라 시도 |

## 확실한 재로딩 절차

페이지 단순 새로고침(F5/Ctrl+R)으로는 부족할 수 있습니다 — Chrome이 content_script를 캐시하거나 `__entrySaveManagerLoaded` 플래그가 유지되는 경우.

```
1. chrome://extensions/ 로 이동
2. Entry Save Manager 카드의 새로고침 ↻ 클릭
   ⤷ 안 들으면: 토글 OFF → ON
   ⤷ 그래도 안 되면: 제거 후 "압축해제 확장 다시 로드"
3. 작품 탭으로 돌아가 Ctrl+Shift+R (캐시 무시 강력 새로고침)
4. 페이지 다 뜬 후 작품 영역 클릭 (user gesture)
5. 콘솔에 출력되는 처음 10~20줄 확인
```

## DEBUG 모드 켜기

스토어 배포 모드는 콘솔이 거의 비어 있어 진단이 어렵습니다. 임시로 켜기:

1. [inject.js](../ES/inject.js): `const DEBUG = false;` → `true`
2. [content.js](../ES/content.js): `const DEBUG = false;` → `true`
3. 확장 재로딩 + 페이지 Ctrl+Shift+R

켜면 다음이 보임:
- `[ESM] [/...] inject.js 로드됨 (MAIN world)` — IIFE 진입
- `[ESM-DBG][inject] [/...] IIFE 시작 — top: ..., 초기 pageType: ..., resolved: ...`
- `[ESM-DBG][inject] [/...] getStorageKey() → entry_save_... (pt: ..., resolved: ...)`
- `[ESM] [/...] 변수 복원: @xxx = ...`
- `[ESM] [/...] toggleRun 후킹 완료`
- `[ESM] [/...] 진입 시 이미 실행 중 — 초기 로드` 또는 `엔진 상태 전이 감지: stop → run`

배포 전엔 다시 false로 되돌릴 것.

## 콘솔 로그 prefix 가이드

| Prefix | 위치 | 용도 |
|---|---|---|
| `[Entry Save Manager]` | inject.js, content.js | 사용자에게 노출되는 운영 메시지 (warn/error만) |
| `[ESM] [/<pathname>/]` | inject.js, content.js | DEBUG 게이팅 일반 로그 |
| `[ESM-DBG][inject] [/...]` | inject.js | DEBUG 게이팅, namespace/핸드셰이크 추적 |
| `[ESM-DBG][content] [/...]` | content.js | DEBUG 게이팅, frame 통신 추적 |
| `[ESM-DBG][popup]` | popup.js (제거됨) | 디버깅 시 임시 추가 |

콘솔 필터 입력에 `[ESM`을 넣으면 우리 로그만 표시.

## 배포 전 셀프 테스트 시나리오

새 버전 배포 직전에 **모두** 통과해야 함:

### 시나리오 1: /project/에서 자동 로드
1. v1.3.x로 작품에 진입
2. `@저장` 호출
3. localStorage에 `entry_save_<id>` 생성 확인
4. 페이지 새로고침
5. 자동 로드되어 변수/리스트가 복원되는지

### 시나리오 2: /ws/와 /project/ namespace 분리
1. /project/<id>에서 변수값 A로 저장
2. /ws/<id>에서 진입 — 자동 로드 시 A로 복원되지 **않아야** (다른 namespace)
3. /ws/에서 다른 값 B로 저장
4. localStorage에 `entry_save_<id>`(A)와 `entry_save_ws_<id>`(B) 둘 다 존재

### 시나리오 3: @가져오기 교차 작품
1. 작품 X(`/project/<X>`)에서 `@저장`
2. 작품 Y에서 `@가져오기 <X>` 호출 → X의 데이터 적용 확인

### 시나리오 4: /noframe/ 동등 동작
1. `https://playentry.org/noframe/<id>` 진입
2. /project/와 동일하게 자동 로드 / 저장 동작
3. 같은 namespace 키(`entry_save_<id>`) 사용 확인

### 시나리오 5: SPA 라우팅
1. /project/<A>에서 변수 저장
2. SPA 네비로 /ws/<A>로 이동 (전체 리로드 없이)
3. /ws/는 자기 namespace 사용 — A는 안 보여야 정상

### 시나리오 6: 팝업 동작
1. /project/<id>에서 데이터 있는 상태로 팝업 열기
2. "현재 작품 초기화" → `entry_save_<id>`만 삭제 확인
3. /ws/<id>에서 같은 ID 작품 데이터(만약 있다면) 보존되는지

### 시나리오 7: 운영 모드 콘솔 깔끔
1. DEBUG=false로 빌드
2. 정상 동작 후 콘솔에 우리 출력이 거의 없음 (실제 오류만)

## 자주 사용하는 콘솔 트릭

### 강제 자동 로드 트리거
```js
// 자동 실행이 안 일어날 때 직접 토글
window.frames[0].Entry.engine.toggleRun();
```

### 변수 직접 조작
```js
const f = window.frames[0];
const v = f.Entry.variableContainer.variables_.find(x => x.name_ === '@확장프로그램');
v.setValue(1);  // 또는 v.value_ = 1
```

### localStorage 키 일괄 제거
```js
Object.keys(localStorage)
  .filter(k => k.startsWith('entry_save_'))
  .forEach(k => localStorage.removeItem(k));
```

### v1.3.0 잔재만 정리
```js
Object.keys(localStorage)
  .filter(k => k.startsWith('entry_save_project_'))
  .forEach(k => localStorage.removeItem(k));
```

### 후킹 강제 재시도
```js
// inject.js의 함수에 직접 접근 못 하지만 Entry.block을 통해 확인
const block = window.frames[0].Entry.block;
Object.keys(block).filter(k => k.startsWith('func_')).forEach(k => {
  console.log(k, '_isSaveMgrHook:', !!block[k].func._isSaveMgrHook);
});
```

## 수렴 안 될 때

1. 진단 정보 모아두기:
   - 위 4개 진단 명령 결과
   - 콘솔의 `[Entry Save Manager]`, `[ESM]`, 빨간 에러 모두
   - `chrome://extensions/`에서 확장 버전
   - Chrome 버전 (`chrome://settings/help`)
   - 작품 ID + URL 패턴 (`/project/`인지 `/ws/`인지 `/noframe/`인지)

2. [01-문제-해결-기록.md](01-문제-해결-기록.md)의 시간순 기록 훑어보기 — 비슷한 증상 있는지

3. 잠복 버그 가능성 점검 — 특히 환경 변화에 민감한 부분:
   - manifest MAIN world content_script firing 여부
   - 키 형식 변경 후 마이그레이션 동작
   - SPA 라우팅 후 inject.js 재주입

4. 일단 DEBUG=true 켜고 사용자에게 "처음 5초간의 콘솔 로그" 요청
